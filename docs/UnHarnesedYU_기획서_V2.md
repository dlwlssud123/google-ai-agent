# [기획서 V3] 설비 다운타임 최소화를 위한 Workflow 기반 RAG 장애 조치 에이전트

**팀명:** UnHarnesedYU
**팀장:** 이진녕 | **팀원:** 안태언

---

## 1. 개발과제의 개요
기존 산업 현장에서는 장애 발생 시 수백 페이지에 달하는 종이/PDF 매뉴얼에 의존하고 있어 신속한 조치가 어렵고 초기 대응이 지연되는 문제가 있습니다. 본 과제는 이러한 문제를 해결하기 위해, 비정형 매뉴얼 데이터를 활용하여 단계별 조치 절차를 안내하는 RAG 기반 워크플로우 에이전트를 개발하는 것을 목표로 합니다.

기존의 단순 질의응답형 RAG를 넘어, 현재 점검 단계를 기억하고 다음 행동을 지시하는 상태 관리(State Management) 기반 워크플로우를 도입합니다. 특히, 기름 묻은 장갑을 낀 작업자도 쉽게 사용할 수 있도록 원터치 퀵 버튼 중심의 간편한 현장 맞춤형 UI/UX를 제공하여 신속한 대응을 가능케 하고(Magic object), AI의 할루시네이션(환각)을 방지하기 위해 원본 도면 매칭 뷰어를 탑재하여 산업 현장에 요구되는 신뢰성과 안전성을 확보하고자 합니다.

## 2. 과제의 필요성 및 기대효과

### (1) 기존 기술(과제)의 현황, 문제점 및 개선방안
* **현황 및 문제점 1 (기존 현장의 매뉴얼 및 인적 전달 한계):** 대규모 현장을 포함한 기존 현장에도 PDF 혹은 도서 매뉴얼이 존재하지만, 장애 발생 시 신속한 대응이 어려워 초기 대응이 지연되고 작업 효율이 떨어져 경제적 손실로 이어진다. 특히 일부 중소 산업 현장에서는 유지보수 절차가 체계화/문서화되지 않은 사례가 많아 숙련된 작업자들의 구두 전달에 의존하고 있으며, 이로 인해 작업자 간의 기술 편차가 발생하고 신규 인력의 현장 투입에 큰 진입 장벽이 된다.
* **현황 및 문제점 2 (보수적인 현장 특성과 AI 신뢰성 한계):** 생명 및 안전과 직결되는 보수적인 산업 현장에서는 생성형 AI 특유의 환각 현상(Hallucination)으로 인해 AI의 답변을 그대로 신뢰하고 도입하기 어렵다.
* **현황 및 문제점 3 (기존 스마트 기기 조작의 물리적 한계):** 기존 스마트 기기 솔루션은 주로 키보드 타이핑 등 텍스트 입력을 요구하기 때문에, 두꺼운 안전 장갑을 착용한 현장 작업자가 위급한 장애 상황에서 사용하기에 물리적인 한계가 존재한다.
* **개선방안:** 
  - **도메인 특화 지식 기반 RAG:** 사내 매뉴얼 등 도메인 특화 데이터만을 참조하여 답변을 생성하는 RAG 아키텍처를 도입하여 정확도를 높입니다.
  - **에이전틱 워크플로우 (Agentic Workflow):** AI가 점검 순서를 제시하고 `[정상]`, `[비정상]`, `[해당 없음]` 등 큼직한 원터치 버튼으로 작업자의 확인(Human-in-the-loop)을 받으며 다음 단계로 넘어가는 능동형 시스템을 구축합니다. 이를 통해 간편한 UI/UX로 신속한 대응이 가능해집니다 (Magic object).
  - **출처 원본 뷰어 (Document Viewer 팝업):** AI의 답변 출처 뱃지를 클릭하면 해당 PDF 매뉴얼의 원본 페이지를 팝업으로 즉시 띄워줍니다. 작업자가 눈으로 직접 교차 검증할 수 있도록 설계하여 할루시네이션을 철저히 방지합니다.

### (2) 과제개발 혹은 제작에 따른 기대효과
* **경제적 측면:** 설비 장애 발생 시 원인 분석 및 조치에 소요되는 시간을 단축함으로써 설비 다운타임을 최소화하고 경제적 손실을 감소시킬 수 있다.
* **운영적 측면:** 숙련 작업자의 경험에 의존하던 지식을 표준화하여 비숙련자도 신속하게 대응할 수 있도록 지원하며, 일관성과 유지보수 효율성을 향상시킨다.
* **기술적 측면:** 단순 검색 기반의 챗봇을 넘어, 현장 상황에 맞춰 사용자에게 구체적인 조치 절차를 가이드하는 산업용 AI 에이전트의 활용 가능성을 입증한다.

## 3. 과제목표 및 주요 내용

### (1) 과제 수행의 최종목표
* **정량적 목표:** 
  - 검색 정확도: 실제 매뉴얼-키워드 검색 사례를 통한 Retrieval Top-3 Accuracy 기준 95% 이상 달성.
  - 시스템 응답 속도: 최종 사용자 응답 지연 시간 10초 이내 달성 (향후 최적화를 통해 단축).
* **정성적 목표:** 
  - 장갑 착용 상태에서도 조작 가능한 UI/UX (원터치 퀵 버튼).
  - 출처 기반 응답 및 PDF 뷰어 띄우기를 통한 AI 답변의 완전한 투명성 보장(Hallucination 방지).

### (2) 주요 기능 (기능적 요구사항)
* **현장 밀착형 터치 중심 UI (모바일 최적화):**
  - 화면 상단에 `[1. 증상 확인] ➔ [2. 원인 분석] ➔ [3. 현장 조치]` 형태의 시각적 진행 스텝퍼(Progress Tracker) 렌더링.
  - 타이핑 없이 진행 가능한 퀵 액션 버튼(Quick Actions) 제공. 또한 에러를 내놓고 그 뒤에 이어질 수 있는 예상되는 질문 등도 버튼으로 내놓는 워크플로우 지원.
* **출처 매핑 UI 및 신뢰성 검증 뷰어:**
  - AI가 반환한 응답에 포함된 출처 뱃지를 클릭 시, 원본 PDF의 해당 페이지를 즉각 열어주는 Document Viewer 통합.
* **Server-side Data Ingestion (ChromaDB 파이프라인):**
  - 다단 레이아웃과 표가 많은 산업용 PDF를 의미 단위(Semantic)로 청킹하여 ChromaDB에 벡터 데이터로 저장.
* **상태 기반 대화 관리 (State Management):** 
  - 이전 점검 단계 및 작업자 응답 이력을 기반으로 현재 Workflow 상태를 유지 및 관리.
* **채팅 세션 별 데이터 분리:**
  - 각기 다른 설비 장애 상황을 독립적으로 관리할 수 있도록 다중 세션 및 파일 연동 기능 제공.

### (3) 비기능적 요구사항
* **보안 및 환경관리:** LLM API Key 및 DB 엔드포인트를 `.env.local`로 철저히 은닉. 매뉴얼 등 기업 내부 데이터가 외부로 유출되지 않도록 보안 설계.
* **유지보수성:** UI 컴포넌트와 서버 액션 함수를 파일 단위로 엄격히 분리하여 코드 가독성 확보.
* **Fail-safe 응답 구조:** 검색 유사도 점수가 기준 이하일 경우, AI가 임의로 조치 절차를 생성하지 않고 작업자에게 원문 매뉴얼 검토 혹은 숙련 작업자 확인을 요청하도록 설계한다.
* **Human in the loop 구조 적용:** AI는 유지보수 Workflow를 보조하는 역할만 수행하며, 최종 유지보수 판단 및 실제 작업 수행은 작업자가 직접 수행하는 Human-in-the-loop 구조를 적용한다.

### (4) 한계점 및 고도화 방향
#### [한계점]
1. **대상 설비의 제한:** 본 시스템은 제한된 개발 기간 내 안정적인 MVP 구현을 목표로 하므로, 초기 단계에서는 특정 설비 1~2종의 매뉴얼을 대상으로 제한적으로 동작한다.
2. **실시간 데이터 연동 부재:** 현재 버전은 PDF 기반의 정적 매뉴얼 검색 중심 구조이므로, 실시간 설비 상태 데이터 및 센서 정보와의 직접 연동은 지원하지 않는다.

#### [고도화 방향]
1. **음성 인식(STT) 및 물리 버튼 지원:** 화면 터치가 어려운 극한 상황에서도 조작이 가능하도록 음성 서비스와 모바일 기기 물리 버튼(음량 조절 버튼 등)을 통한 제어 기능을 추가할 예정입니다.
2. **IoT 센서 및 실시간 로그 연동:** PDF 기반의 정적 검색을 넘어, 실시간 센서 데이터와 연동하여 장애를 선제적으로 감지하고 능동적으로 분석하는 시스템으로 고도화합니다.

## 4. 추진전략 및 방법

### (1) 추진전략 및 방법
본 과제는 산업 현장의 보수적인 특성(안전 최우선)과 제한된 개발 기간 내 안정적인 프로토타입 구현을 위해 '도메인 지식 기반의 신뢰성 확보(RAG)'와 '신속한 프로토타이핑(Rapid Prototyping)'을 핵심 방법론으로 채택하여 진행한다.

**1) 문제 해결 접근법: RAG 가드레일 프롬프팅 도입**
* 범용 AI의 최대 취약점인 환각 현상(Hallucination)을 해결하기 위해 검색 증강 생성(RAG)을 적용한다.
* LLM이 사전 학습된 지식을 기반으로 임의 응답을 생성하지 않도록 제한하고, 오직 검색된 사내 매뉴얼 텍스트 내에서만 정답을 추출하도록 강제하는 '가드레일 프롬프트 엔지니어링' 기법을 적용하여 응답의 안전성을 확보한다.

**2) 자료 수집 및 데이터 전처리 방안**
* **타겟 도메인 한정:** 문제 발생 빈도가 높은 특정 설비(예: 핵심 모터 또는 펌프류) 1~2종의 공식 PDF 매뉴얼로 초기 수집 데이터를 한정하여 MVP 구현에 집중한다.
* **의미 기반(Semantic) 청킹:** 다단 레이아웃, 표 등 복합 구조를 포함하는 산업용 문서 특성을 반영하여 의미 기반 청킹 전략을 적용해 검색 정확도를 극대화한다.

**3) 환경 구축 및 개발 방법론**
* 프론트엔드와 백엔드를 단일 프레임워크(풀스택, Next.js)로 구축하여 네트워크 연동 및 통신 구조의 복잡도를 최소화한다.
* 개발 절차는 2단계의 애자일(Agile) 스프린트(Core Logic ➔ UI & Integration)로 나누어 진행한다.

**4) 시스템 검증 및 평가 방안**
* 30개의 실제 매뉴얼-키워드 검색 사례(Test Case)를 사전에 정의하여 시스템 성능을 정량적으로 평가한다.
* Retrieval Top-3 Accuracy, Citation Precision, 평균 응답 시간 등을 측정한다.
* AI가 제시한 조치 절차와 출처 정보가 실제 매뉴얼 내용과 일치하는지 교차 검증하고 RAGAS 기반 평가 지표를 참고하여 신뢰성을 극대화한다.

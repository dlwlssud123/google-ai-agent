# [기획서 V2] 설비 다운타임 최소화를 위한 에이전틱(Agentic) RAG 장애 조치 시스템

**팀명:** UnHarnesedYU
**팀장:** 이진녕 | **팀원:** 안태언

---

## 1. 개발과제의 개요
본 과제는 산업 현장에서 설비 장애 발생 시, 작업자가 방대한 종이/PDF 매뉴얼을 탐색하느라 발생하는 **초기 대응 지연 및 설비 다운타임 문제를 해결하기 위한 '행동 유도형(Agentic) AI 장애 조치 에이전트'** 개발을 목표로 합니다. 
기존의 단순 질의응답형 RAG(검색 증강 생성)를 넘어, **현재 점검 단계를 기억하고 다음 행동을 지시하는 상태 관리(State Management) 기반 워크플로우**를 도입합니다. 특히, 기름 묻은 장갑을 낀 작업자도 쉽게 사용할 수 있도록 **터치리스(음성) 및 원터치 퀵 버튼 중심의 현장 맞춤형 UI/UX**를 제공하며, AI의 할루시네이션(환각)을 원천 차단하기 위해 원본 도면 매칭 뷰어를 탑재하여 산업 현장의 최고 수준 안전성과 신뢰성을 확보하고자 합니다.

## 2. 과제의 필요성 및 기대효과

### (1) 기존 기술의 한계점과 본 과제의 개선 방안
*   **현황 및 문제점 1 (검색의 비효율성):** 중소 제조 현장의 유지보수 절차는 두꺼운 비정형 PDF 도면과 숙련자의 경험(구두 전달)에 의존하고 있어 신규 작업자의 현장 투입이 어렵습니다.
*   **현황 및 문제점 2 (현장 UI 부적합성):** 기존 챗봇이나 모바일 솔루션은 키보드 타이핑을 요구하여, 두꺼운 안전 장갑을 착용한 현장 작업자가 위급한 장애 상황에서 사용하기 매우 어렵습니다.
*   **현황 및 문제점 3 (AI에 대한 불신):** 생성형 AI 특유의 환각 현상으로 인해, 생명과 직결되는 산업 현장에서는 AI의 임의적 판단을 신뢰하지 않는 보수적인 성향이 짙습니다.

*   **💡 개선 방안 (UnHarnesedYU만의 차별점):**
    1.  **에이전틱 워크플로우 (Agentic Workflow):** 작업자가 질문을 던지는 것이 아니라, AI가 매뉴얼을 분석해 먼저 점검 순서를 제시하고 `[정상]`, `[비정상]`, `[해당 없음]` 등 **큼직한 원터치 버튼**으로 작업자의 확인(Human-in-the-loop)을 받으며 다음 단계로 넘어가는 능동형 시스템을 구축합니다.
    2.  **출처 원본 뷰어 (Document Viewer 팝업):** AI의 답변 출처 뱃지를 클릭하면, 단순 페이지 번호 표기를 넘어 **해당 PDF 매뉴얼의 원본 페이지를 팝업으로 즉시 띄워주고 하이라이팅**합니다. 작업자가 눈으로 100% 교차 검증할 수 있도록 설계합니다.
    3.  **약점의 강점화 (왜 IoT 센서가 아닌 비정형 RAG인가?):** 공장 고장의 상당수는 센서 에러보다 물리적 부품 마모/결함에서 비롯되며, 이는 센서 데이터보다 '매뉴얼과 작업자의 경험'에 의존합니다. 따라서 **아직 완벽히 디지털화되지 않은 '비정형 도면의 지식화 및 절차화'**를 MVP의 최우선 해결 과제로 삼았습니다.

### (2) 기대효과
*   **경제적 측면:** 설비 다운타임을 분 단위로 단축하여 생산 중단으로 인한 막대한 경제적 손실 방어.
*   **운영적 측면:** 비숙련자도 베테랑 수준의 표준화된 조치를 수행할 수 있게 되어 기술 편차 해소.
*   **기술적 측면:** 단순 LLM Q&A를 넘어선, 진정한 의미의 'Task-oriented Agent(목표 지향형 에이전트)' 시스템의 산업 현장 적용 사례 창출.

## 3. 과제목표 및 주요 기능

### (1) 최종 목표
*   **정량적 목표:** 실제 에러 코드 30개 기준 Retrieval Top-3 Accuracy 95% 이상. 평균 응답 지연 시간 3초 이내.
*   **정성적 목표:** 장갑 착용 상태에서도 조작 가능한 UI/UX, AI 답변의 완전한 투명성 보장(Hallucination 0%).

### (2) 주요 기능 (기능적 요구사항)
1.  **현장 밀착형 터치/음성 중심 UI (모바일 최적화):**
    *   화면 상단에 `[1. 증상 확인] ➔ [2. 원인 분석] ➔ [3. 현장 조치]` 형태의 **시각적 진행 스텝퍼(Progress Tracker)** 렌더링.
    *   타이핑 없이 진행 가능한 퀵 액션 버튼(Quick Actions) 제공 및 음성 인식(STT)을 통한 증상 입력 지원.
2.  **Server-side Data Ingestion (ChromaDB 파이프라인):**
    *   다단 레이아웃과 표가 많은 산업용 PDF를 의미 단위(Semantic)로 청킹하여 ChromaDB에 벡터 데이터로 저장.
3.  **Fail-safe 및 100% 신뢰성 검증 뷰어:**
    *   검색 유사도가 기준치 미달이면 즉시 임의 답변을 중지하고 관리자 호출을 유도하는 Fail-safe 로직.
    *   응답에 포함된 인용구 뱃지를 클릭 시, 원본 PDF의 해당 페이지를 즉각 열어주는 Document Viewer 통합.

## 4. 추진전략 및 방법

### (1) 개발 방법론 (MVP 중심 애자일)
*   복잡한 백엔드를 분리하기보다는 Next.js 기반 풀스택 프레임워크를 활용해 네트워크 병목을 최소화하고 UI와 RAG 코어 로직 간의 통신 속도를 극대화합니다.

### (2) 시스템 검증 (RAGAS 도입)
*   단순 체감 성능이 아닌, **RAGAS 프레임워크**(Faithfulness, Context Precision 등)를 도입하여 AI가 매뉴얼 범위를 벗어난 대답을 하는지 정량적으로 차단하고 평가합니다.

## 5. 추진일정 및 역할 분담 (기존 유지)
*   **이진녕 (팀장):** 풀스택 아키텍처, ChromaDB 인제스천 파이프라인, 에이전틱 워크플로우 상태 관리 엔진 개발.
*   **안태언 (팀원):** 프롬프트 엔지니어링, 장갑 착용자를 위한 모바일 최적화 UI(진행 스텝퍼, 원터치 버튼), 원본 도면 연동 Document Viewer 구현.
